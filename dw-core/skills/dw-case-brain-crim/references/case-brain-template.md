# Case Brain Document Template

**For use by `dw-case-brain-crim`. Internal reference. Do not file.**

This is the canonical template for a Case Brain stored in the Obsidian vault at `DW-CASE BRAINS/Cases/[LastName]-[FirstName].md`. It defines the YAML frontmatter contract and every body section. The vault renders the YAML as Obsidian "Properties" for search and filtering; the body is the human-readable case memory.

The order, names, and casing of the body H2 sections below are part of the contract. Companion skills and the "full brief" command (Step 5) parse these section headers — do not rename them.

---

## YAML Frontmatter (required)

Every Case Brain begins with this frontmatter block. Fields marked `VERIFY` should be filled if known and otherwise left as `VERIFY` so the attorney is reminded to confirm at next session.

```yaml
---
tags:
  - case-brain
  - active                       # or "closed"
  - [charge-type]                # weapons | homicide | sex-offense | drugs | dwi | white-collar | other
  - [phase]                      # phase-0 | phase-1 | phase-2 | phase-3
status: active                   # active | closed
phase: "0 — Intake"              # "0 — Intake" | "1 — Discovery & Analysis" | "2 — Motions" | "3 — Trial / Plea Prep"
client_name: "First Last"
docket: "C-XXXXXX"
court: "Court Name, Section X"
parish: "Parish Name"
lead_attorney: "Christopher Washington"
charges: "Charge 1, Charge 2"
date_of_offense: YYYY-MM-DD
date_of_arrest: YYYY-MM-DD
next_court_date: "VERIFY"        # YYYY-MM-DD or VERIFY
prosecutor: "VERIFY"
judge: "VERIFY"
lwop_risk: false                 # true if any charge carries LWOP exposure
co_defendants: ""                # comma-separated names, or empty
gdrive_root: "Drive Name"        # CALCASIEU PDO Files | NOLA Conflict Cases | D&W Law Firm (CJW)
gdrive_path: "/Users/greatelephant82/Library/CloudStorage/GoogleDrive-cjw@danielswashington.com/Shared drives/[Drive Name]/[Client Folder]"
CASE_ROOT: "/Users/greatelephant82/Library/CloudStorage/GoogleDrive-cjw@danielswashington.com/Shared drives/[Drive Name]/[Client Folder]"
last_updated: YYYY-MM-DD
---
```

**Key field rules:**

- `CASE_ROOT` and `gdrive_path` MUST hold the same absolute path. Every D&W skill that writes a file reads `CASE_ROOT` from this frontmatter to construct its output path.
- `tags` is a YAML list and must include `case-brain` plus exactly one of `active`/`closed`. Charge-type and phase tags are optional but recommended for filtering.
- `phase` value is the human-readable phase string used in the SESSION OPEN CONFIRMATION banner.
- `last_updated` is auto-updated by `dw-case-brain-crim` on every session close.

## 4. Theory of Case / Defense Narrative

**Sub-sections:**

- **Strongest facts for defense:** [Bullet list — facts that support the theory]
- **Strongest facts against defense:** [Bullet list — facts the State will lean on, and how we plan to neutralize them]
- **Theory mode:** [Denial-of-act | Mistaken-identity | Self-defense | Lack-of-intent | Affirmative defense X | Mixed]

## 5. Phase Status & Quality Gates

The case moves through 4 phases (0 → 3). For each phase, list the gating deliverables and their status.

### Phase 0 — Intake
- [ ] Initial client interview completed
- [ ] Conflict check cleared
- [ ] Engagement / appointment confirmed
- [ ] Bond / release status documented
- [ ] Discovery request served

### Phase 1 — Discovery & Analysis
- [ ] Discovery received and indexed
- [ ] DMAR (Defense Media Analysis Report) completed
- [ ] Phone dump analyzed
- [ ] Body cam / dash cam reviewed
- [ ] Crime scene audit completed (if applicable)
- [ ] Confession / interrogation audit (if applicable)
- [ ] Eyewitness ID audit (if applicable)
- [ ] Brady / Giglio audit completed
- [ ] Discovery compliance ledger maintained

### Phase 2 — Motions
- [ ] Motion to suppress (if grounds exist)
- [ ] 404(B) opposition (if Prieur notice filed)
- [ ] Bond reduction motion (if applicable)
- [ ] Motion in limine (if applicable)
- [ ] Discovery motions (compel, particulars)

### Phase 3 — Trial / Plea Prep
- [ ] Witness threat matrix
- [ ] Cross-exam outlines
- [ ] Voir dire / jury selection plan
- [ ] Jury instructions submitted
- [ ] Trial notebook assembled
- [ ] Plea negotiation analysis (if a plea is being considered)
- [ ] Sentencing mitigation package (if conviction occurs)

## Updating Procedure (Cross-Reference)

When `dw-case-brain-crim` writes session updates, only these sections change:

| Section | Update Mode |
|---|---|
| YAML frontmatter | Update changed fields only; preserve unchanged fields |
| 1. Case Overview narrative | Update if new facts emerged |
| 5. Phase Status | Tick or untick checkboxes |
| 6. Key Evidence | Append new flagged items |
| 7. Open Issues | Add new issues; mark resolved with `[x]` and date |
| 8. Key Decisions Log | Append-only — never delete or rewrite past decisions |
| 9. Session History | Prepend new session entry |
| 10. Companion Skill Outputs | Append new rows for new outputs |
| 11. Next Steps | Replace entirely |

Sections 2 (Charges & Exposure), 3 (Case File Locations), and 4 (Theory of Case) are updated only when the underlying facts genuinely change — not on every session.
